## Goal

A patient asks about their own reports and gets an answer that names its source: "Fasting sugar was 126 mg/dL (Lab report, page 2)." The assistant reads reports back. It doesn't interpret them, it refuses diagnosis and dose questions, and a family member sees records only while consent is valid.

S4 must prove three things:

- **No patient can ever see another's data**, even with a poisoned PDF in the index.
- **Every number in an answer really is in the page it cites.**
- **A value read from a scan is flagged as one**, because S3 found about 1 scan-read number in 200 is wrong.

## What you need to provide

- **Nothing new to start.** The OpenRouter key from S2 is used, so please keep it working. If you revoked the pasted key and didn't replace it, run `make key-from-clipboard` first.
- **Cost:** my estimate is under $2 per full live eval run. Each report prints the actual cost.
- **Your own questions (step in the test pack).** Reports and questions you write are the independent check. You can ask them without any files to save.

## In scope

1. **Eval set first, committed before any graph or prompt** (`evals/w2/ask.jsonl`)
   - At least 30 cases on the S3 synthetic reports, with an expected answer, page and document. Spec's hard cases are included: another patient's question, questions the record can't answer, red-team PDFs.
   - English, Hinglish and Hindi questions; comparing two reports; a value that appears on a scanned page.
   - Red-team set: planted instructions, **including the reworded ones S3's filter missed**, hidden text, and requests to read another patient.
   - **A guard against S2's slip:** a test fails if any prompt shares a run of 5 or more words with an eval case. S2's prompt echoed its test wording by accident, and this makes that visible.
2. **Ask graph** (`sahyog/graphs/w2_ask.py`), as the spec lays it out, plus one step at the start:
   - `red_flag → scope_guard → retrieve → grade_context → (widen once) → answer → safety_check → respond`.
3. **Red-flag gate first (not in the spec; my addition).** Someone asking about a report may write "my chest has been hurting since I saw this". W2 reuses W1's gate: rules, then the model second pass. On a flag, they get the emergency message and an ER ticket, and no answer. A failed second pass goes to the desk.
4. **Scope guard**
   - The caller is the patient, or a caregiver with a consent row that matches grantee, scope and purpose and hasn't expired. **Checked on every read and never cached.** Expired consent gets 403 and no data, and is audited.
   - `patient_id` in the request is checked against that, and the search filter comes from the auth context, never the model.
   - Diagnosis and dose questions get a fixed refusal and a desk ticket, using the same check as W1.
5. **Answering**
   - Output schema: sentences, each with its citations (`doc_id`, `page`). Only numbered excerpts go to the model, and it cites by excerpt number, so it can't invent a document id.
   - The gateway scrubs excerpts before they leave. S2's limitation applies: some names outside the name list can reach OpenRouter.
   - Answers come in the patient's language; values stay exactly as printed.
   - **Nothing in the record means no answer:** "I couldn't find that in your reports", never a guess from general knowledge.
6. **Safety check, in code, before anything reaches the patient**
   - Every citation resolves, and belongs to this patient, or the answer is blocked and an incident is logged. Blocked answers get a fixed message.
   - **Number check (not in the spec; my addition):** every number in the answer must appear in a chunk that sentence cites. Otherwise it's blocked. This costs no model call and catches invented or changed values.
   - Clinical wording: diagnosis or dose language in the answer blocks it.
7. **Scan warning, added by code rather than the model.** If an answer cites a scan-read chunk, a fixed line is added: this value was read from a scanned page, so please check it against the original on page N. A model can't forget it.
8. **API and try-it commands**
   - `POST /w2/ask` with `{question, patient_id}` returns `{answer, citations, handoff?}` as a stream.
   - **The answer streams only after the safety check.** Streaming as it's written would show text that might then be blocked. So the 8-second target has to cover the whole check.
   - `make ask patient=P0011 q="..."`, and for a caregiver, `make ask patient=P0011 as=CG0011 q="..."`. `make eval-live set=ask`.
9. **Evals**
   - Faithfulness with ragas 0.4, by a model acting as judge. **Uncalibrated in S4**, so reported beside the deterministic checks and never the only gate. Calibrating against 20 human-graded answers is S7's job, as already planned.
   - Prompts frozen before measuring, each blind set measured once, as in S2.

## Decisions for this stage

| Decision | Choice | Why |
|---|---|---|
| Streaming | Only after the safety check | A blocked answer must never be partly shown. Answers appear all at once, so it feels slower |
| Citations | Model cites excerpt numbers, and code maps them to documents | It can't invent a document id, and foreign ids are also checked |
| Number check | Exact match against cited chunks | Free and deterministic. It can't catch S3's misreads, since those are already in the chunk, which is why the scan warning exists |
| Faithfulness judge | Uncalibrated and never the only gate | A model grading a model needs human calibration first (S7). The deterministic checks carry the gates |
| Foreign data | SQL filter is the defence | No prompt, poisoned or not, can widen a WHERE clause. The red-team set proves it end to end |
| Identifiers in answers | Placeholders restored only for the caller | The name in an answer can only be this patient's or one already in their own report |
| Prompt and case overlap | Mechanical test | Disclosure didn't stop S2's slip from happening |
| Memory | The API loads the embedding model for search | Estimated 2–3 GB, on Docker's 8 GB. The test pack will give the measured figure |
