## What's built

One plain web app with no build step, served by the API (`sahyog/web/`). It holds no clinical logic: every rule stays behind the API.

- **Patient:** describe symptoms, answer a question, pick a block, get a token. Upload reports and see status. Ask about reports, with the page on each sentence and the scan warning. See appointments.
- **Family caregiver:** read a patient's reports while consent is valid.
- **Doctor:** choose a patient, type, record or upload a dictation, read what was heard, edit the draft, fill gaps, reject or sign.
- **Front desk:** the queue in order, with reason, owner and age. Claim, close and cancel with a reason.

Also added: `/dev/login`, on only when `DEV_LOGIN` is set (`docker-compose.yml` sets it locally), `GET /w1/appointments`, `/w2/documents` and `/w3/appointments`, all scoped by the token and audited.

## Checks

Clicked through in a real browser on the real model:

| Flow | Result |
|---|---|
| Hinglish symptoms to a suggested specialty and three doctors | Worked |
| Pick a block, get a token in Hinglish | Worked |
| Stroke wording | Emergency banner, no doctors, ticket on the desk |
| Ask about a scanned report | Sentences with pages and a scan warning |
| Caregiver with valid consent; caregiver with expired consent | Answered; refused |
| Bad file upload | Plain refusal shown |
| Doctor: draft, sign refused with an open gap, fill it, sign | Worked, hash shown |
| Desk queue at phone width in dark mode | Clear, red flags first |
| Audio upload to the real worker | Worked by API |

**Not tried:** the microphone button, since this browser has no microphone; a successful upload by clicking through the file picker (bad file only, and good files through the API); a move override on screen (the screen offers cancel only, while the API also moves); the patient language selector, since language is detected. Tested by Claude only, not by a person or a screen reader. Keyboard focus styles and labels are present, but accessibility wasn't audited.
