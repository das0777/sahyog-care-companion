## Goal

Build every safety part the graphs will rely on, and prove each one with a measured eval, **before any graph exists**. After S1 we can say, with numbers:

- an emergency is caught by fixed rules before any model sees the text;
- nothing that identifies a patient leaves the hospital boundary;
- every model call goes through one gateway that checks its output, falls back and is metered.

S2 then builds the W1 graph on these parts instead of inventing them inside it.

## In scope

1. **Red-flag engine** (`sahyog/safety/red_flags.py`)
   - Reads `Specialty.red_flag_rules` (the global list plus each specialty's own phrases) from the database. The rules stay data, not code.
   - Matches **concepts, not exact strings**. Each rule has synonyms in English, Hinglish (Latin script) and Hindi (Devanagari), so "seene mein dard", "सीने में दर्द" and "chest pain" are one concept.
   - Tolerates typos ("chest pian", "breathlesness") with fuzzy matching on word windows.
   - **Combination rules** catch emergencies that no single phrase names. Example from the spec: "dull ache left arm, breathless since morning, age 62, diabetic" fires because arm pain plus breathlessness, together with age ≥ 40 or diabetes, is a cardiac pattern.
   - Returns `{red_flag, rules_fired[], matched_text[], route}`, with `route = "emergency_desk"` on a flag. Every decision says which rule fired and on which words, so it can be audited.
   - **Fails safe:** negation does not cancel a flag. "No chest pain since morning" still flags in S1, and these false alarms are counted (see Decisions).
   - **The model can add flags, never remove them.** A `second_pass` hook merges model-suggested flags by union. A test feeds a model reply that says "not an emergency" and checks the flag stays. The real model call is wired in S2.
2. **Language detection** (`sahyog/safety/language.py`)
   - Labels text `en`, `hi` (Devanagari) or `mixed` (Hinglish or two scripts), using script ranges plus a Hinglish word list. No model.
   - The red-flag engine and, later, `match_specialty` both use the label.
3. **De-identification and egress scrubber** (`sahyog/safety/deid.py`)
   - Presidio analyzer and anonymizer with spaCy, plus custom recognisers for:
     - ABHA numbers (with or without hyphens or spaces);
     - Indian phone numbers (+91, 0-prefixed, spaced, and the seed's +91 55 range);
     - pincodes, emails and Aadhaar-like 12-digit numbers.
   - **Known-identifier pass:** when a call is about a patient, the scrubber also takes that patient's own name, phone, ABHA and date of birth from the database and removes every form of them. This catches Indian names that a general NER model misses.
   - **Generalises instead of deleting where the spec says so:**
     - date of birth becomes an age band ("60–69");
     - pincode becomes a district (a small table for the seeded cities; unknown pincodes are removed).
   - Replaces direct identifiers with placeholders (`<PERSON_1>`, `<PHONE_1>`). The placeholder map stays in memory for that one call, so a reply can be re-identified before it reaches the user. It is never sent out and never stored.
   - **Keeps clinical content:** lab values, units, medicines and dates of tests survive, because over-scrubbing would break W2 and W3. This is measured.
4. **Model gateway** (`sahyog/llm/`)
   - One `ModelGateway` interface. Graphs never import a vendor SDK, and a test fails if any module outside `sahyog/llm/adapters/` does.
   - Every call declares:
     - a task class (`small`, `large`, `in_region`) that maps to a model in settings;
     - a pydantic output schema;
     - a timeout;
     - a fallback;
     - the trace id from the auth context.
   - **Order inside every call:** scrub → call model → validate the JSON against the schema → re-identify. Output that fails the schema is **rejected, never repaired**, and the caller gets a typed error.
   - Adapters:
     - **`FakeModel`**: scripted, deterministic replies keyed by task and input, and it records every payload it receives. All tests and `make eval` use it, so S1 needs no API key.
     - **`AnthropicModel`**: Sonnet 5.5 for `large`, Haiku 5.5 for `small`. Built and unit-tested against a stubbed HTTP layer. It is exercised for real only by an optional `make llm-smoke`, once you have added your key to `.env`.
     - **`OllamaModel`**: the in-region fallback. Built and unit-tested the same way. Running a real Ollama is optional.
   - **Fallback:** when the primary times out or errors, the gateway retries once, then calls the configured fallback with the same trace id and records which provider answered.
   - **Cost meter:** token counts per call, priced from `config/prices.yaml`, which records the date of the price list. Prices are never hard-coded in Python.
5. **Eval harness** (`sahyog/evals/`, data in `evals/`)
   - **`evals/w1/golden.jsonl`: 30 W1 cases** in the spec's format (`id`, `input`, `expect`, `must_not`, `source`, `author`). Roughly:
     - 12 red flags: English, Hinglish, Devanagari, typos, and combination patterns like the spec's arm-pain case;
     - 18 non-emergencies with an expected specialty, including two symptoms pointing at two specialties, negated red-flag words ("no chest pain, just a cough"), and mixed-language text.
   - The expected specialty is written now, but specialty accuracy is first measured in S2, when the matcher exists. The rule from the PRD is that evals come before graphs.
   - **`evals/egress/`: 200 outbound payloads**, generated deterministically from seeded patients. They are realistic requests a graph would send (triage text, record questions, note snippets), with identifiers in many formats:
     - names inside sentences;
     - phones written five ways;
     - ABHA with and without hyphens;
     - dates of birth in four formats;
     - pincodes and emails.
   - **The replay detector is independent of the scrubber.** It knows the ground truth (every identifier value of every seeded patient, normalised) and searches the scrubbed payloads that `FakeModel` actually received. A hit is reported with the payload id.
   - **`evals/fixtures/malformed/`:** model outputs that are truncated JSON, have missing fields, use the wrong types, carry extra prose, or put a diagnosis where a specialty should be. Every one must be rejected.
   - **`make eval`:**
     - runs all of the above;
     - prints a report table with target, result and pass or fail;
     - writes `evals/reports/s1-<date>.md` and `.json`;
     - exits non-zero on any gate failure.
   - **`make eval GUARDRAILS=off`:** the same run with the red-flag gate and scrubber switched off. It must fail loudly. This proves the evals actually test the guardrails (the spec's rule: each guardrail has a case that fails when it is removed).
6. **Try-it commands for you**
   - `make redflag text="…"` prints the language, the decision, the rules that fired and the matched words.
   - `make scrub text="…" patient=P0001` prints the scrubbed text and the placeholders. The map itself is shown only in this local command.
7. **Docs**
   - `docs/adr/0002-safety-before-models.md`: why rules run before models, fail-safe on negation, and reject-never-repair.
   - `docs/safety/red-flag-rules.md`: how rules are written and that a clinician must review them.
   - README section on `make eval`.

## Decisions for this stage

| Decision | Choice | Why |
|---|---|---|
| Negation | Does not cancel a red flag in S1 | A missed emergency costs far more than a false alarm. The false-alarm rate is measured (B3) and can be tuned later with clinician input |
| Matching | Concept synonyms + fuzzy word windows + combination rules, no model | Deterministic, explainable, testable; the spec requires rules before any model call |
| Name detection | spaCy small English model plus the known-identifier pass | The large model adds about 500 MB to the image and still misses many Indian names. Using the patient's own record is more reliable |
| Placeholder map | In memory for one call; never stored or sent | Nothing needs it after the reply is re-identified. Storing it would create another copy of identifiers |
| Output schema | Reject, never repair | Repairing hides model errors and can invent fields; the spec says reject |
| Eval data | Synthetic only, generated from the S0 seed, with source and author on every case | Same data everywhere; no real patient text |
| Same author for rules and cases | Claude writes both. B2 is your independent check, and the S2 golden cases are added before the S2 rules change | 100% recall on cases written by the same author as the rules proves less than it sounds; your own phrasings are the honest test |
| API key | Not needed for S1 | Everything runs on `FakeModel`; `make llm-smoke` is optional |
