## Goal

A stack that comes up with one command, holds the full data model with realistic synthetic data, knows who is calling and in what role, and writes an audit row for every patient-record read. No AI yet: every later stage builds on this.

## In scope

1. **Repository and tooling**
   - Python 3.12 managed by `uv`, `pyproject.toml`, `ruff` for lint and format, `pytest`.
   - A `Makefile` as the single entry point: `up`, `down`, `migrate`, `seed`, `test`, `lint`, `token`, `reset`.
   - `.env.example` with every setting. `.env` is git-ignored. No secrets in the repo.
2. **Docker Compose stack**
   - `postgres`: Postgres 16 with pgvector (`pgvector/pgvector:pg16`).
   - `redis`: Redis 7.
   - `minio`: object store, with `reports` and `audio` buckets created on start. The 24 h lifecycle rule on `audio` is set here and tested in S5.
   - `api`: the FastAPI app, hot-reloading from the source folder.
   - Langfuse is deferred to S7 so the stack stays light.
3. **Data model: all 14 tables from the spec**, created by Alembic migrations.
   - Patient, Consent, Document, DocChunk, Doctor, Specialty, Clinic, Slot, Appointment, Encounter, ClinicalNote, Prescription, MedicineStock, AuditEvent.
   - Slot as a **block**: `starts_at`, `ends_at`, `capacity`. Appointment carries `token_no`, `checked_in_at`, `consult_started_at` and `consult_ended_at`, per decision E2.4.
   - DocChunk has `embedding vector(1024)` with an HNSW index and a `tsvector` column, created now and used in S3.
   - Database-level rules:
     - AuditEvent is append-only: a trigger rejects UPDATE and DELETE.
     - Signed ClinicalNote rows are immutable (a trigger).
     - Appointment is unique on `idempotency_key`.
     - Appointment is unique on `(slot_id, token_no)`.
4. **Synthetic seed data**: deterministic, with a fixed random seed, so every run produces identical data.
   - 38 specialties, each with starter red-flag phrases. The S1 rule engine reads these.
   - 12 clinics in 4 cities.
   - 500 doctors, with languages from English, Hindi and Marathi.
   - 14 days of one-hour blocks, capacity 4–6, clinic hours only: about 42k Slot rows.
   - 1,000 patients with fake ABHA IDs and Indian names and phones from Faker `en_IN`, clearly marked synthetic.
   - 50 caregiver consents (some expired, to test S4).
   - Medicine stock for each clinic.
   - No real person's data anywhere.
5. **Identity, kept simple as agreed.** A dev token issuer replaces OIDC.
   - `make token role=patient id=P0001` prints a signed JWT (HS256, local secret).
   - Roles: patient, caregiver, doctor, desk, pharmacist, compliance.
   - Every request builds an auth context: who, role, purpose (from a `X-Purpose` header) and trace id.
6. **Audit on every record read (E6.1).** A shared dependency writes one AuditEvent per patient-scoped read: actor, role, purpose, table, record id, action, time, trace id. A failed audit write fails the request; we never read without logging.
7. **First endpoints**, to prove the plumbing:
   - `GET /health` reports Postgres, Redis and MinIO separately.
   - `GET /me` returns the caller's auth context.
   - `GET /patients/{id}`: a patient sees only themself; a doctor or desk sees any; it is audited.
   - `GET /doctors?specialty=&city=`: not patient-scoped, so not audited.
   - `GET /audit?record_id=` is for compliance only and answers "who saw this record?" in one query.
8. **Docs**
   - `README.md` with setup in under 10 commands.
   - `docs/data-contracts/` with one short contract per table: owner role, sensitivity class, checks.
   - `docs/adr/0001-stack.md` recording the stack choice.

## Acceptance checklist (what you will verify)

| # | Check | How |
|---|---|---|
| A1 | Stack starts from clean with one command | `make up` → all 4 containers healthy |
| A2 | Health reports each dependency | `curl localhost:8000/health` → `postgres`, `redis` and `minio` each show `ok` |
| A3 | Schema matches the spec | `make migrate` creates 14 tables; `make test` includes a schema test |
| A4 | Seed is complete and repeatable | `make seed` twice → identical counts: 38 / 12 / 500 / ~42k / 1,000 |
| A5 | Roles are enforced | Patient P0001 reading P0002 → 403; doctor reading P0002 → 200 |
| A6 | Every record read is audited | After A5, `GET /audit?record_id=P0002` as compliance shows both attempts with actor, role and purpose |
| A7 | Audit cannot be altered | An `UPDATE` on `audit_event` in psql is rejected by the trigger |
| A8 | A slot cannot be overbooked at the database level | Test inserts the same `(slot_id, token_no)` twice → second insert fails |
| A9 | No secrets committed | `.env` git-ignored; `git grep` for keys finds none |
| A10 | All tests green | `make test` passes; `make lint` is clean |

## Test pack you will receive

- A report table: each check A1–A10 with Claude's own result.
- A copy-paste script running A1–A10 in order, with the expected output after each command.
- Known limitations, stated plainly.

## Decisions for this stage

| Decision | Choice | Why |
|---|---|---|
| Python toolchain | Python 3.12 via `uv` | 3.12 matches the spec; `uv` is already installed and fast |
| ORM and migrations | SQLAlchemy 2 + Alembic | Standard choice; the LangGraph Postgres checkpointer shares the same database |
| Auth | Local HS256 dev tokens | User direction: keep auth as in the reference, don't build it out |
| Block size | One hour, capacity 4–6 | Matches the block-booking decision; can be tuned per clinic later |
| Ports | API 8000, Postgres 5433, Redis 6380, MinIO 9100/9101 | Checked on 2026-10-29: zerowire's `local-zbackend` holds 9000 and a Redis holds 6379, so these are offset to avoid clashes |
