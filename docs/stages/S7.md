## What's built

- **Circuit breaker** in the gateway: after 5 failures in a row a provider gets no calls for 30 seconds, then one trial. Per process.
- **Traces:** `trace_span`, one row per model call, with no prompt text. `make ops` prints the tiles. Postgres, not Langfuse (ADR 0004).
- **Cost per consultation:** the formula from traces, with prices from `config/prices.yaml`. Infrastructure prices are marked as placeholders.
- **Worker heartbeat** in `/health`.
- **MCP server** (`sahyog/mcp_server.py`): `search_doctors`, `list_slots`, `reserve_slot`, `stock_lookup`, with identity from the token and the same audit. Tested by calling its tools and listing them, not from a real MCP client.
- **Eval cases:** W1 141 with probes, W2 84, W3 40, as the Pro tier asks. The W2 and W3 additions were written after their prompts were frozen, and each was measured once.
- **Judge calibration tool:** `make eval-live set=ask-calibrate`. Waiting on a person.
- **Load test:** `make load`.
- **ADRs 0004 and 0005**, a demo script, and the final report.

## This build: S4's word checks on unseen rewordings (pull request #18)

S4's review (#13) asked S7 to measure `asks_for_advice_on_records` and `clinical_answer` on rewordings nobody tuned on. The independent reviewer of #18 wrote 70 inputs before reading the checks (`evals/w2/unseen/`, rerun with `measure.py`):

| | English | Hinglish | Hindi | All |
|---|---|---|---|---|
| Advice questions sent to a person | 4/10 | 2/8 | 0/7 | 6/25 (24%) |
| Read-back questions wrongly refused | 1/4 | 1/3 | 0/3 | 2/10 (20%) |
| Clinical answers blocked | 9/10 | 5/8 | 5/7 | 19/25 (76%) |
| Read-back answers wrongly blocked | 1/4 | 0/3 | 0/3 | 1/10 (10%) |

**What this means:** the question check is a weak backstop, weakest in Hindi, where it caught none. The answer check catches three in four. Neither can be the main defence, so the model's own diagnosis-or-dose flag and the answer prompt carry that, and these lists only catch what slips past them. The set was written by Claude, so it's unseen but not independent.

## What this doesn't prove

- **The load test is a Mac, with one API process and a small data set.** It shows the code doesn't fall over at this rate. It says nothing about production capacity, and 7 minutes isn't a soak.
- **Triage's miss and pass overlap.** The run at the target rate was slower than the run at three times it, which is noise from the provider and from small samples. Treat triage as near the limit, not as passing.
- Three model calls in about 600 failed with an error whose cause wasn't logged at the time. All went safely to the desk, and the gateway now logs the provider's message.
- Gemini passed only sets the prompts were tuned on.
- **Spec items not done:** Langfuse, per-node traces, ragas, the calibrated judge, the operations screen (tiles are a command).
