# D7 · Threat model

The pack's five flows, then one row for each STRIDE class they don't cover. **Proof** names the test or eval that fails if the control is removed. "Not built" is stated where it's true.

| Flow | Threat (STRIDE) | Control in this build | Proof |
|---|---|---|---|
| Ask my record | Instructions in an uploaded PDF make the assistant read another patient's chunks (information disclosure) | The patient filter in SQL, behind `can_read`. Citations' owners checked. Another patient's ID gets "not found" | `test_search_stays_inside_the_patient_and_audits_each_document`, `test_foreign_chunk_reaching_the_answer_is_blocked`, `test_a_question_naming_another_patient_gets_no_answer`, and the W2 red-team set (MVP live: 0 leaks in 26) |
| Find my doctor | Scripted bookings hoard slots (denial of service) | One active booking per patient, idempotency keys, a capacity lock | `test_no_double_booking_under_50_concurrent_patients`, `test_idempotency_key_unique`. **Not built: rate limits per patient and address, and OTP at booking.** The pack's 1,000-bookings test hasn't been run |
| Scribe | A note is edited after signature (tampering) | A DB trigger makes signed notes immutable; the API returns 423 and audits | `test_signed_note_is_immutable` |
| Egress | Identified text ends up in a vendor's log (information disclosure) | Scrubber on the gateway, placeholder map on site, identified system prompts refused | `test_identifiers_are_scrubbed_before_leaving_and_restored_after`, `test_system_prompt_with_an_identifier_never_leaves`, the egress replay (B5: 0 of the patient's identifiers in 200). **Other people's names can leak. No zero-retention contract** |
| Data at rest | A database dump walks out (information disclosure) | **Not built:** no encryption at rest, the app connects as the DB superuser, no access review | None |
| Sign-in | Someone acts as another patient or role (spoofing) | Signed tokens, role from the token, identity never from the request body or the model | `test_missing_and_bad_tokens_rejected`, `test_access_rule_for_another_patients_record`. **Dev tokens only, OIDC not built, the default dev secret isn't refused at startup** |
| Any record read | A user denies having read a record (repudiation) | Every read audited, including denials, before data returns; the audit table is append-only by trigger; a failed audit write fails the read | `test_every_attempt_is_audited_including_denials`, `test_failed_audit_write_fails_the_read`, `test_audit_update_rejected`, `test_audit_truncate_rejected` |
| Roles and consent | A caregiver or staff role reads beyond its rights (elevation of privilege) | Consent checked on every read, with scope, purpose and expiry; desk and MCP actions role-checked and audited | `test_consent_is_checked_on_every_read`, `test_expired_consent_returns_no_data_and_is_audited`, `test_mcp_refuses_the_wrong_role_and_a_bad_token`. **Open:** doctor and desk roles can read any patient's demographics |
